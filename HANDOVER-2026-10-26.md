## Improvement discipline

Each change names its owner and gets a new version. A release pins every module
and input by hash. Characters cannot inherit each other. Shared changes expand
the impact set. Existing canaries remain. Passing all canaries is necessary; an
affected comparison also needs an owner-observed improvement. A model preference
or technical media pass cannot certify creative success. An exact owner decision
promotes only the standards pointer, never a post or generation request.

Actual production dialogue, grades and media stay private because this repository
is public. A private bundle is needed on another machine; code alone does not
reconstruct its missing state. Do not attach private bundles to a pull request or
public Actions artifact. Fresh-process behaviour can be proved locally; future
model compliance and another machine's access remain separate observations.
